## Statically established behavior

- The launch default is headless; `use_rviz:=true` is explicit.
- YAML topic/frame values are authoritative unless the corresponding launch argument is explicitly non-empty; namespace remains independently configurable and empty by default.
- Default relative outputs remain `/unilidar/cloud` (`PointCloud2`, `unilidar_lidar`) and `/unilidar/imu` (`Imu`, `unilidar_imu`) with best-effort, volatile, keep-last depth 10.
- SDK2 work-mode bits 5–31, 2D mode, transport mismatches, and wait-for-start mode are rejected before SDK initialization. IMU-disabled mode requires `publish_imu_tf=false` and ignores unexpected IMU packets.
- `use_system_timestamp=false` is rejected because no hardware-clock-to-ROS-time conversion exists.
- The dynamic `unilidar_imu_initial -> unilidar_imu` transform uses the normalized SDK `x,y,z,w` quaternion and exactly the IMU message timestamp. Its physical reference-frame direction and sign semantics remain hardware-unverified.
- The code-inherited `unilidar_imu -> unilidar_lidar` transform is configurable and sent through `/tf_static`.
- A measured robot-to-IMU static transform is disabled by default, has no numeric defaults, and cannot coexist with the dynamic parent of `imu_frame`.
- Invalid parameters and nonzero initialization results result in a nonzero process status; successful transport is closed during normal destruction.
- Launch/config/RViz resources have install rules and the target verification script checks the installed paths plus `--show-args` without starting the driver.
- SDK selection remains Linux-only and exact for `aarch64` and `x86_64`, with the build-tree selection recorded in `unitree_sdk_library.txt`.
- No `/scan`, navigation, fusion, serial bridge, command, or motor behavior was added.

These bullets remain source-contract claims. The separate Pi evidence now verifies C++ compilation/linking, the selected ARM64 archive, installed resources, and launch argument parsing for this working tree. It does not verify physical runtime behavior.
